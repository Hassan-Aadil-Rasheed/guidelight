# Spoken place suggestions — 0.8.1

Physical validation on 28 October 2026: the user confirmed that numbered suggestions are read aloud, Wispr choice input works, and version 0.8.1 selects the requested place. This resolves the selection issue reported during the earlier 0.8.0 test. References to pending confirmation below describe the earlier investigation, before this user confirmation. This test does not establish reliability across all interruptions or validate route safety.

After a successful search, GuideLight reads every result in screen order as “Suggestion 1”, “Suggestion 2”, and so on, including the place name, approximate distance and short address. Numbers stay attached to that result list. Even a single result requires an explicit choice.

Use the paired Selfie button once to begin, wait for the vibration, say “Choose suggestion two”, and press again to submit through Wispr Flow. Without the remote, tap Choose by voice and dictate with the Wispr bubble. The ordinary editable field switches to choice input while the original destination remains intact in application state. Stable inserted text is processed after 1.2 seconds. Starting dictation stops GuideLight's speech so it does not keep reading suggestions into the microphone.

Supported commands include numeric and spoken choices, for example “Choose suggestion 2”, “Select option number two”, “Pick the second one” or simply “2”. “Repeat suggestions” reads the entire list again. “Change destination” returns to destination entry. Unknown, ambiguous and out-of-range commands give a spoken correction and retain the suggestions rather than launching a search or selecting a different place.

The choice screen uses the activity's existing Compose/Material components instead of a separate modal window. This keeps both the hardware key callback and the focused Wispr input in GuideLight's main window. Version 0.8.1 keeps the same editable Compose node and keyboard configuration through search and suggestions; destination and choice values remain separate in application state. Touch selection remains available with the same suggestion numbers. Lists and controls scroll with large fonts.

Speech uses Android's existing TextToSpeech engine. Each suggestion is queued with QUEUE_ADD after the initial QUEUE_FLUSH so later suggestions do not interrupt earlier ones; long utterances respect getMaxSpeechInputLength. See the [Android TextToSpeech reference](https://developer.android.com/reference/android/speech/tts/TextToSpeech). No additional speech subscription, recorder or service was added. Wispr still manages its own microphone and transcription.

UI checks cover choice-field focus, preserved destination, numbered results, repeat controls and 200% text. The integration check exercised actual search → simulated Wispr choice text → automatic route creation. Version 0.8.0 (code 12) was installed and opened on the OPPO, and both Accessibility services remained enabled. Actual spoken playback and Wispr/remote choice selection on the OPPO are awaiting the user's physical confirmation.

A moving overlay no longer triggers release solely because it moved away from the original point.
