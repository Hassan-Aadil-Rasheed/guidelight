Physical confirmation on 28 October 2026: the user confirmed that spoken cautions stay silent while dictating with Selfie/Wispr and that the end-walk/Yes flow works. The user also confirmed that object outlines appear in the Camera tab without starting a walk. This closes both reported issues; the pending notes below describe the earlier investigation.

Once a walking route starts, the same paired Selfie button can control Wispr on the walking screen. Press once, wait for the phone's ready vibration, say the command, then press again to submit. Without the remote, tap Speak a command and use the Wispr bubble. The ordinary command field accepts Wispr text without changing the destination or route.

- “Repeat directions” reads the latest warning, when present, and the current turn instruction.
- “End walk” stops the current walk directly. “End the walk”, “Stop navigation” and “Finish the walk” are accepted alternatives.

Use one press → speak → press cycle for each command. Unknown, mixed or negated commands leave the walk active and provide a spoken correction. A bare “stop” or a camera warning does not count as an end-walk command.

The spoken command bypasses the end confirmation. Touch controls retain their existing inline confirmation in the activity's main window, and the walking editor remains mounted. The Selfie callback accepts the Navigate screen during an active walk.

The 1.2-second text debounce is bound to the current route session and confirmation state. Pending commands are discarded when that context changes. Arrival and ending a route clear pending voice commands. From 0.9.2, arming input immediately stops GuideLight playback and every app utterance passes through the same dictation mute check. Cautions, stop alerts, directions and suggestion speech remain silent through recording, release, Wispr submission and the text debounce. Detection, visible warnings, GPS state and vibration continue. Speech resumes after processing, cancellation or error; suppressed utterances are discarded rather than queued. A 45-second timeout releases an abandoned manual input session, and leaving Navigate or backgrounding the app cancels it. The bridge retains its separate recording/submission timeouts. The optional bridge still cannot independently observe Wispr's microphone state.

Diagnostic logs record only action kinds such as REPEAT or END; they do not record command text, destinations or audio.
